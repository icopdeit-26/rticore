# Historical Finance event reconciliation — staging gate
Run only against an authorized staging copy using a dedicated read-only PostgreSQL identity. Set RTICORE_RECONCILIATION_SCOPE=staging, RTICORE_STAGING_EXPECTED_DATABASE and RTICORE_STAGING_DATABASE_URL (sslmode=verify-full) securely on the server. Run node scripts/finance-historical-reconciliation.mjs. No payloads or credentials are printed. A clean digest scan is not financial reconciliation or proof of authenticity. For each exception, independently match the original approved contract, timesheet, PO, invoice or FlexGuard ledger and associated journal/audit records; preserve historical evidence. Do not simply rehash the old payload or replay processed events. Use separately approved corrective events and Finance Controller sign-off. Record source counts, balances, exception disposition, exact SHA and reviewer; zero unresolved exceptions is mandatory. Actual staging execution is outstanding.
